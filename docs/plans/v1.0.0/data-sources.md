# データソースと更新フロー

PO 方針: 過去は政府 CSV、来年は発表時期に Actions で取得、未来の未確定は演算。

## 政府 CSV

- 内閣府等が公開する「国民の祝日」CSV（いわゆる `syukujitsu.csv`）を正の過去・確定データとする
- **最古年は 1955**（公開 CSV の先頭年。N-D1。**2026-10-20 PO 承認**）
- 文字コードは Shift_JIS 等の可能性あり。パース時に変換する（参照: life の `parse-jp-holiday-csv.mjs`）
- 1 行: 日付と名称。日付を `YYYY-MM-DD` に正規化し、年ごとの JSON オーバーライドへ落とす

## 年ごとの解決（N-D1。2026-10-20 PO 承認）

| 年 | データ源 |
|----|----------|
| 1948 未満 | 空配列（＋任意の `onWarning`。N-H1） |
| **1948〜1954** | **祝日法に基づく演算**（政府 CSV に該当年が無い） |
| **1955 以降（CSV 入手可能年）** | CSV 由来の **override**（ある年にファイルがあれば演算しない） |
| 未来で override 無し | 演算 |

CSV による override は **CSV を入手できる年（1955 年以降）に限る**。1948〜1954 を手作業で override 化しない。

## リポジトリ内の置き場（案）

```
src/
  data/jp-holiday/
    source/          # 取得した CSV（必要なら git 管理）
    override/        # 年ごと JSON（例: 2024.json）
scripts/
  fetch-jp-holiday-csv.*   # 取得（Actions から呼ぶ）
  parse-jp-holiday-csv.*   # CSV → override JSON
```

パスは実装時に調整してよい。意味の分離（source / override / scripts）は維持する。

## オーバーライド JSON

```json
[
  { "title": "元日", "date": "2026-01-01" },
  { "title": "成人の日", "date": "2026-01-12" }
]
```

- ファイル名は西暦でも、各要素の `date` には必ず西暦を含める
- その年の全日分を列挙する（部分上書きではない）。ある年にファイルがあれば演算を使わない

## 来年分の更新（Actions）

ワークフロー: [`.gitea/workflows/fetch-holiday-csv.yml`](../../../.gitea/workflows/fetch-holiday-csv.yml)（U-09 / D-18。**2026-10-20 PO 承認**）

1. 政府が翌年分を公表した時期に、ワークフローを手動（`workflow_dispatch`）またはスケジュールで実行
2. CSV を取得
3. パースして `override/`（および生成マップ）を更新
4. **feature ブランチへ push し PR を作成**し、人が確認してからマージする
5. **main への直 push はしない**

### 運用上の前提（PO 承認済み 2026-10-20）

| 項目 | 内容 |
|------|------|
| 成果物 | PR 作成のみ（自動マージしない） |
| 必須 secret | リポジトリ secret **`GITEA_TOKEN`**（ブランチ push と Gitea API での PR 作成に使用） |
| secret 欠如時 | PR 作成ステップを失敗させる（黙ってスキップしない） |
| 取得失敗時 | ワークフローを失敗させ、古いデータのままリリースしない |

## 過去分の初期投入

- **CSV 入手可能年（1955〜最新確定年）**を、一度 CSV から生成してコミットする（N-D1）
- **1948〜1954** は初期投入の対象外（演算パス。N-D1）
- life リポに既にある override / source があれば、ライセンスと出自を確認のうえ移植してよい

## ランタイムとの関係

- 公開 API はディスクや HTTP にアクセスしない
- オーバーライドはビルド成果物またはバンドル内データとして同梱する
- 「最新 CSV を実行時に読む」は v1 スコープ外

## テスト観点（データ）

- パース: 代表行・空行・不正行の扱い
- 生成 JSON が型（title/date）を満たすこと
- 既知年（例: 2024, 2025）で政府公開と一致すること
- オーバーライドがある年に演算パスが呼ばれないこと（単体でスタブまたは分岐カバレッジ）
