# harenohi

## このプロジェクトについて

**各国・各文化圏の祝日を演算し返すライブラリ**を作る。当初は npm パッケージ（TypeScript）。将来 OSS として公開する。

社内カレンダー系プロダクト（例: `@b4m/final-calendar`）や個人アプリから祝日判定を共通利用できるようにする。既存の祝日演算は `kohki/shikata-kohki-life` に TypeScript 実装がある。これを再利用・切り出して本パッケージの核とする。

## スコープ

### やる（v1.0.0 まで）

- 祝日演算 API の定義と実装
- **日本の祝日**の定義・演算・取得
  - 法令で定まる日は動的演算
  - 春分・秋分は動的だが概算（公布と異なっても当面許容）
  - 政府 CSV 由来の過去データ取り込み、および来年分の取得フロー
- 戦後の現行祝日法以降を対象とする

### やらない（現時点）

- 日本以外の文化圏・国の祝日（`After-v1.0.0`）
- 祝日法制定以前の歴史的祝祭日
- UI / カレンダー描画（利用側の責務。例: final-calendar）
- 営業日・銀行休業日の独自カレンダー提供（祝日の上に利用側が重ねる想定）
- 時刻・タイムゾーン変換そのもの（日付 `YYYY-MM-DD` のみ扱う）

## 主な責務

1. 指定した日付・年・月について、祝日かどうかを判定する
2. 祝日の一覧（名称と日付）を返す
3. 日本祝日データの生成方針に従い、演算と静的データ（オーバーライド）を組み合わせる

## 日本祝日データの生成方針

PO 初期メモの意図を維持する。詳細は [plans/v1.0.0/japan-holidays.md](plans/v1.0.0/japan-holidays.md) と [plans/v1.0.0/data-sources.md](plans/v1.0.0/data-sources.md)。

| 区分 | 方針 |
|------|------|
| 未来の祝日 | 法令で定まる日は動的演算。春分・秋分は概算演算（公布差分は許容） |
| 来年の祝日 | 政府発表時期に Actions で CSV を取得し、パースしてライブラリに追加 |
| 過去の祝日 | 政府公表 CSV を取り込みパース。現行祝日法以降。それ以前はスコープ外 |

オーバーライド（年単位の静的 JSON）がある年は、演算結果より静的データを優先する（参照実装と同じ考え方）。

## 技術方針

| 項目 | 方針 |
|------|------|
| 言語 | TypeScript |
| 実行環境 | Node.js およびブラウザ |
| 日付 | `YYYY-MM-DD` 文字列。時刻は扱わない |
| 外部日付ライブラリ | 初期は依存を最小化する（未決: Day.js を残すか純自前か） |
| アーキテクチャ | パッケージのため薄い DDD の CRUD Trait は不要。純関数の演算層を中心とする（憲章の「CLI・パッケージ」例外に従う） |
| 参照実装 | `kohki/shikata-kohki-life` の `src/utils/holiday/` |
| 配布 | 当面は社内 npm。将来 `@b4moss/harenohi` として OSS 公開（名前空間は未決参照） |
| テスト | 憲章の TDD・氷山パターン。単体を厚め。E2E は不要 |
